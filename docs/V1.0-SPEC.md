# Tomica 典藏庫 V1.0 系統規格

規格日期：2026-08-22  
狀態：Draft，作為第一版實作與 GitHub Repository 的需求基線。

## 1. 產品定位

Tomica 典藏庫不是單純的車款清單，而是以「每一件實際收藏品」為中心的管理系統。同一車款可擁有不同年份、產地、配色、底盤、輪胎、包裝、保存狀況及取得來源；包裝標示與車體也可能不一致，系統必須能分別記錄並標記疑點。

## 2. V1.0 範圍

### 必做

- 儀表板：總收藏數、不同車款數、盒裝／散車、近期新增、待確認項目。
- 藏品管理：新增、查看、編輯、複製、刪除、封存。
- 車款與版本：Tomica 編號、系列、名稱、製造商、比例、配色、年份、產地、底盤文字、輪胎型式。
- 包裝管理：盒裝／吊卡／其他、包裝編號、包裝狀況、是否原配、缺件。
- 照片管理：主圖、車頭、車尾、左右側、車頂、底盤、包裝正反面、細節照。
- 搜尋與篩選：編號、名稱、品牌、系列、產地、年份、狀況、包裝、標籤、關鍵字。
- 收藏資訊：取得日期、來源、價格、幣別、存放位置、備註。
- 資料交換：JSON 完整備份／還原、CSV 匯入／匯出。
- 重複與疑點提醒：相同編號與主要特徵提示；包裝編號與車體不一致可標記待考證。
- RWD：手機可快速拍照建檔，桌面可高密度整理。

### V1.0 不做，但預留

- 多人帳號與權限。
- 即時跨裝置同步。
- AI 自動辨識車款。
- 市價追蹤、交易與公開收藏頁。
- 條碼資料庫或外部 Tomica 資料源串接。

## 3. 核心概念

| 名稱 | 定義 | 範例 |
| --- | --- | --- |
| 車款 Master Model | 現實世界的車型或 Tomica 基本模具資料 | Honda Freed |
| 發行版本 Release | 某次正式發行的商品／系列編號、配色、年份與規格 | Event Model No.08 |
| 實際藏品 Item | 使用者手上那一台實物 | 有盒、底盤刮痕的個體 |
| 包裝 Package | 與實際藏品分開保存與判定 | No.08 紙盒，但可能非原配 |
| 圖片 Photo | 隸屬藏品或包裝的影像 | 底盤、盒底、輪胎特寫 |
| 疑點 Issue | 待查證或不一致資訊 | 外盒 No.08、底盤資訊不同 |

資料關係：一個車款可有多個發行版本；一個發行版本可對應多件實際藏品；藏品可有零或多個包裝、照片、標籤及疑點。

| 頁面 | 主要內容 | 關鍵操作 |
| --- | --- | --- |
| 首頁／儀表板 | 統計卡、近期新增、待確認、收藏分布 | 快速新增、繼續編輯 |
| 我的典藏 | 卡片／表格切換、搜尋、條件篩選 | 批次標籤、匯出、排序 |

## 5. 藏品建檔流程

1. 拍攝或選擇主圖。
2. 搜尋既有車款／版本；找不到時建立新資料。
3. 填寫實際個體的底盤、輪胎、狀況及取得資訊。
4. 加入包裝並選擇「確認原配／疑似原配／非原配／未知」。
5. 系統檢查必填欄位、疑似重複及包裝不一致。
6. 儲存後進入詳情頁；未完成資料可標為「待補資料」。

## 6. 欄位規則

### 車款與版本

- 顯示名稱、原文名稱、製造商、Tomica 系列、商品／系列編號。
- 「商品／系列編號」與「底盤刻印編號」必須分開儲存，不得視為同一欄位或互相覆蓋。
- 底盤刻印編號允許三種狀態：有編號、明確無編號、尚未確認；「明確無編號」不得與空白或未知混為一談。
- 另設「底盤原文刻印」欄位，依實物逐字保存品牌、比例、車名、產地與其他文字。
- 發行類型：一般、初回特別仕様、Premium、Limited、活動限定、店鋪限定、其他。
- 發行年份可只填年份；未知資料允許留空，不可用推測值覆蓋事實。
- 比例可填 `1/64` 或標記 `No Scale`。
- 底盤文字應保留原樣另設標準化欄位，方便搜尋。

### 實際藏品

- 不再以 `TMC-年份-流水號` 作為使用者看到的館藏編號。
- 藏品顯示編號依序採用：商品／系列編號 → 底盤刻印編號 → 「無編號」。
- 同一商品編號有多件藏品時，以個體序號或取得資訊區分；資料庫仍使用不可變的內部 UUID 保證唯一性。
- 狀況分級不取代細項描述；至少分車體、輪胎、底盤、玻璃、內裝、包裝。
- 收藏狀態：持有、預購、借出、出售、交換、遺失、封存。
- 資料完整度：完整、待補照片、待查版本、待補取得資訊。

### 包裝

- 包裝資料與藏品分表，允許無盒、孤盒、多個附件。
- 原配判定必須有「未知」，避免系統自行斷言。
- 可記錄包裝尺寸及保護套／束帶需求。

### 圖片

- 支援拖曳、相機拍攝、排序與設定主圖。
- 上傳時生成縮圖，保留原圖；顯示目前圖片容量。
- 照片類型使用固定選單並允許「其他」。

## 7. 搜尋、排序與篩選

- 單一搜尋框同時查名稱、編號、品牌、底盤文字、館藏編號及備註。
- 常用快速篩選：待查證、無盒、有盒、近期新增、重複候選、照片不足。
- 複合條件可疊加，且顯示目前啟用的篩選籤。
- 排序：新增日、修改日、Tomica 編號、車名、取得日、價格、狀況。
- 空值與未知值獨立呈現，不與「無」混為一談。

## 7.1 編號規則與已確認實例

| 藏品 | 商品／系列編號 | 底盤刻印編號 | 其他分類資訊 | 備註 |
| --- | --- | --- | --- | --- |
| Tomica Event Model Nissan Fairlady 240ZG Patrol Car | Event Model No.08 | No.58 | 歷史／收藏分類 No.44-2 | 商品編號與底盤編號不同，兩者均須保留 |
| Tomica Event Model Mazda Cosmo Sport | Event Model ★★ No.21 | 明確無編號 | — | 底盤原文：`tomica ©TOMY / S=1/60 / COSMO SPORT / MADE IN VIETNAM` |

顯示與判定規則：

1. 商品、活動或系列上的 No. 為「商品／系列編號」。
2. 車底模具上的 No. 為「底盤刻印編號」，不可用來覆蓋商品／系列編號。
3. 底盤未刻 No. 時，記錄為「明確無編號」，並完整保存底盤原文。
4. 商品沒有編號時，藏品列表可用底盤刻印編號作為替代顯示編號。
5. 商品與底盤都沒有編號時顯示「無編號」，但仍由內部 UUID 唯一識別。

## 8. UI/UX 基線

### 視覺語言

- 風格：收藏櫃＋檔案館，重視照片但保有資料密度。
- 主色：Tomica 感的紅色作為操作強調色；深藍／炭黑作為導覽與深色模式底色。
- 狀態色：綠＝已確認、黃＝待補、橘＝待查、紅＝異常；不得只靠顏色傳達。
- 卡片主圖比例統一，避免不同照片尺寸造成跳動。

### 桌面版

- 左側固定導覽；上方為全域搜尋與快速新增。
- 我的典藏預設可切換照片卡片與高密度表格。
- 詳情頁採雙欄：左側相簿，右側核心資料；其餘用分段頁籤。

### 手機版

- 底部導覽：首頁、典藏、新增、搜尋、設定。
- 新增按鈕置中突出；建檔支援逐步表單與自動暫存。
- 拍完底盤、盒底照片後可直接指定照片類型。

### 易用性

- 新增與編輯頁固定顯示儲存狀態，離開未儲存頁面前警告。
- 所有刪除先進回收區，避免立即永久刪除。
- 對話框只用於短任務，完整建檔使用獨立頁面。
- 對未知資料採「留空／未知」，不強迫填入不確定答案。
- 關鍵操作按鈕保留文字，不只使用圖示。

## 9. 儀表板 V1.0

- 收藏總數、不同版本數、有盒比例、待查證數。
- 最近 10 筆新增或修改。
- 待處理清單：缺主圖、缺底盤照、包裝不一致、版本未確認。
- 簡易分布：品牌、系列與製造國；點擊後進入套用篩選的典藏頁。

## 10. 資料與備份策略

- V1.0 使用 IndexedDB，避免照片與大量資料受 localStorage 限制。
- JSON 為完整備份格式，包含資料版本、匯出時間、資料列及圖片清單。
- CSV 僅用於主要文字欄位交換，不承載圖片。
- 每次結構變更增加 `schema_version` 並提供資料遷移。
- 還原前先驗證檔案版本與摘要；不得直接覆蓋現有資料而無確認。

## 11. 非功能需求

- 支援最新版 Chrome、Edge、Safari 行動版。
- 常用操作在 1,000 件藏品下應保持流暢。
- 主要頁面具備鍵盤操作、清楚焦點與可讀對比。
- 圖片採延遲載入；列表只讀取縮圖。
- 所有日期以 ISO 格式保存，介面依台灣格式顯示。
- 金額同時保存數值與幣別。

## 12. V1.0 驗收標準

- 可新增一筆含車款、版本、實體狀況、包裝與多張照片的藏品。
- 同一版本可建立兩件以上實體藏品且資料互不覆蓋。
- 可記錄「外盒編號與底盤／車體資訊疑似不一致」。
- 可從搜尋或複合篩選找到指定藏品。
- 可匯出完整 JSON，清空測試資料後成功還原。
- 手機與桌面均能完成核心流程。
- 資料錯誤或未知時不會被系統自動補成確定資訊。

## 13. 開發與版本管理

- Repository 建議名稱：`tomica-collection`。
- `main`：可發布版本；`develop`：整合測試；功能分支使用 `feature/...`。
- 版本格式遵循 Semantic Versioning：`v1.0.0`。
- 每個正式版本更新 `CHANGELOG.md` 並建立 Git tag。
- GitHub Pages 從 `main` 或部署 workflow 發布；發布前通過基本功能與備份還原測試。

## 15. V1.0 開發前需確認的產品決策

1. 系統名稱是否正式採用「Tomica 典藏庫」。
2. Repository 名稱是否採用 `tomica-collection`。
3. V1.0 是否先以單機 IndexedDB 為正式資料來源。
4. 同一商品／系列編號有多件藏品時，介面採用「個體 1、個體 2」或取得日期作為區分方式。
5. 首批匯入是否需要從現有 Excel、照片資料夾或其他清單轉入。
